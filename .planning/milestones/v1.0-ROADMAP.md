# Roadmap

## Milestone 1: NestJS Backend Template v1.0

**Goal:** Production-ready NestJS DDD template that the team can clone and use immediately, with agent configs pre-wired.

**Done when:** A developer can clone this template, run `pnpm install && pnpm dev`, and have a running DDD-structured NestJS service with docs, health checks, and agent configs in under 10 minutes.

---

### Phase 1: Template Scaffold

**Goal:** Build a standalone NestJS 11 skeleton from scratch with one ExampleModule demonstrating full DDD + CQRS structure (Item domain).

**Requirements:** REQ-001

**Plans:** 1/3 plans executed

Plans:
- [ ] 01-PLAN-01.md — Scaffold NestJS project + shared DDD base classes (AggregateRoot, ValueObject, DomainEvent)
- [ ] 01-PLAN-02.md — ExampleModule domain and application layers (Item entity, CQRS handlers)
- [ ] 01-PLAN-03.md — Presenter layer (controller + module wiring) + Dockerfile

**Deliverables:**
- `nestjs-backend-template/` directory in workspace
- Cleaned NestJS app (no business code)
- One `ExampleModule` demonstrating DDD structure
- pnpm workspace setup, Dockerfile, .env.example
- Passing `pnpm build`

---

### Phase 2: DDD Foundation & Infrastructure

**Goal:** Implement full DDD base classes and pre-configured infrastructure modules (Prisma, Redis, Config, Health).

**Requirements:** REQ-002, REQ-003

**Plans:** 3 plans

Plans:
- [ ] 02-01-PLAN.md — DDD base classes: Entity, AggregateRoot refactor, Repository interface, built-in VOs, unit tests
- [ ] 02-02-PLAN.md — Infrastructure modules: ConfigModule, DatabaseModule (Prisma), CacheModule (Redis), HealthModule
- [ ] 02-03-PLAN.md — ExampleModule completion: PrismaItemRepository, CQRS handler wiring, AppModule integration

**Deliverables:**
- `src/shared/` — Entity, ValueObject, AggregateRoot, DomainEvent, Repository interface
- Built-in Value Objects (IdValueObject, StringValueObject, NumberValueObject, DateValueObject)
- DatabaseModule (Prisma), CacheModule (Redis), ConfigModule, HealthModule
- Unit tests for DDD base classes
- `/health` endpoint

**Goal:** Establish API conventions (versioning, response envelope, pagination, error codes), Scalar documentation, and production observability.

**Requirements:** REQ-004, REQ-005, REQ-006

**Plans:** 3/3 plans executed

Plans:
- [x] 03-01-PLAN.md — Shared types (DTOs, exceptions, error codes) + common layer (filters, interceptors, decorators, middleware) + unit tests
- [x] 03-02-PLAN.md — OTel instrumentation + main.ts rewrite (Scalar, versioning, Pino, pipes, filters) + AppModule wiring
- [x] 03-03-PLAN.md — ExampleModule Swagger decorators + HealthController @RawResponse + RedisService OTel spans

**Deliverables:**
- URI versioning at `/api/v1/`
- Response envelope + PaginationDto + AppException
- Scalar docs at `/docs` with auth
- Pino structured logging with correlation IDs
- OpenTelemetry + Prometheus (feature-flagged)
